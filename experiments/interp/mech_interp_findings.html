Why does a detailed rubric hurt gpt-oss-20b?

Behavioral replication + a first mechanistic look (logit lens & causal activation patching) at a judge-specific rubric-sensitivity effect on BFF-Bench, following the method of Wang et al. 2025, "When Truth Is Overridden".

TL;DR

  • Confirmed behaviorally, with the real rubric. Grading BFF-Bench with the benchmark's own published human-annotator guidelines (not a rubric we wrote) drops gpt-oss-20b's agreement with humans (κ 0.667→0.617) while most other judges are unaffected or improve. Removing just the one rule that requires solution steps to match the reference — not only the final answer — fully restores gpt-oss-20b (κ 0.666).
  • gpt-oss-120b does not show this effect (0.677→0.680) — it's specific to the 20B checkpoint, not the gpt-oss family.
  • A mechanistic cause was found — but for a different, stricter rubric we wrote ourselves to probe the phenomenon, not the real one. Under that rubric, gpt-oss-20b's verdict flip is caused by a late, highly localized, almost switch-like internal computation (layer ~22 of 24): patching just three layers there recovers the correct verdict 81% of the time.
  • That mechanism does not explain the real rubric's effect. Probed the same way (a single forced-choice token, no reasoning), the real rubric barely moves gpt-oss-20b's verdict at all. The real effect most likely depends on step-by-step reasoning that a single forward pass can't perform — an open question, not yet answered mechanistically.

Two rubrics, not one

Early in this investigation, a rubric was constructed from scratch to probe the phenomenon. It turned out to differ substantially from the rubric actually used to create BFF-Bench's underlying human labels (Appendix A.4 of Setlur et al., "No Free Labels"). Both are shown below so results can be attributed to the correct one.

RuleResearcher-writtenPaper's Appendix A.4
Final answerMust match within ~1% numeric toleranceMust match the reference
Method / stepsMust be the "standard" method for the question typeMust match the reference's steps — this is the only rule that distinguishes the two rubrics behaviorally
CompletenessEvery part of a multi-part question must be answered → else incorrectnot mentioned
AssumptionsNo unsupported assumptions allowednot mentioned
Units / signMust be exactly correctnot mentioned
Rounding slipsExplicitly INCORRECT even with right method ("no partial credit")Explicitly CORRECT — rounding/approximation is protected
Extra infonot mentionedExplicitly CORRECT if not obviously wrong
Missing infoCounted against completeness → incorrectJudgment call; lean CORRECT (or "Unsure") if unclear

The real rubric is strict on exactly one axis (does the solution process match the reference?) and explicitly lenient everywhere else. The researcher-written rubric compounds six independent strictness conditions, several of which directly contradict the real rubric's leniency clauses. They share one real idea — process matters, not just the final number — but are not interchangeable, which is why the mechanistic results below only hold for one of them.

Inside the model: per-layer verdict (logit lens)

At every layer, the hidden state is read out through the model's own final norm + unembedding (the "logit lens") to see what the model would answer if it had to decide right then. The gap between the standard-prompt curve and the rubric-prompt curve shows where, internally, the rubric starts changing the model's mind.

Causal test: does patching the layer actually flip the verdict?

Correlation isn't causation — so for each item where the rubric flipped the verdict, the hidden state at its own critical layer(s) was swapped between the two prompt conditions and the model was re-run, to see if the verdict follows the activation.

Suppression: patch the "better" condition's activation into the "worse" run — does the correct verdict come back? Induction: the reverse — does patching the "worse" activation into a correct run break it? gpt-oss-20b's asymmetry (recovers almost every time, rarely breaks) looks like a late, near-binary gate. Qwen's roughly symmetric, window-insensitive pattern looks like a softer, more distributed shift — a genuinely different mechanism, not just a weaker version of the same one. Both results are for the researcher-written rubric only (window = number of consecutive layers patched jointly, centered on each item's own critical layer).

Honest scope of these findings

What this page does not show: a confirmed mechanism for the real, published rubric's effect on gpt-oss-20b. The logit-lens/patching pipeline used a single forced-choice token with no reasoning allowed; under that setup the real rubric produces almost no verdict change (1 flip out of 459 items) — not enough to patch. The mechanistic findings above (late critical layer, 81% causal suppression) are solid for the researcher-written rubric, which is behaviorally a different, broader intervention. Reproducing this mechanism for the real rubric likely requires letting the model reason before reading its final-token activations — not yet done.
