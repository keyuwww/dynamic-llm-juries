Does the AI judge know more than it says?

We used a small model, Qwen3.5-0.8B, as a judge: it reads an answer and says good or bad. Then we looked inside it to see whether it had worked out the right call but didn't say it.

This matters for the next step. Editing a model's weights can remove a blockage, but it can't add knowledge the model doesn't have. So first we had to check whether the knowledge is there at all.

1. What it says

The judge's own verdict: how strongly it leans "good" vs "bad".

2. What it knows

A simple detector reads the judge's internal numbers while it decides, and predicts good/bad from those alone.

3. Shortcut check

How well do cheap clues alone do, like "this source usually writes bad answers"? Scores are compared only among answers from the same source, so the detector can't win by spotting who wrote the answer.

Details: methods, all numbers, caveats
  • Judge: Qwen3.5-0.8B, thinking off, verdict read from the next token after "VERDICT:". All items: 2,059.
  • Headline numbers (chart above): 5-fold cross-validation grouped by question/pair/prompt, scored within groups that share the shortcut: same answer model (BFF), same response model and refusal style (Safety), same category (JudgeBench).
  • The held-out test split (columns below, probe layer chosen on a separate dev split) agrees; BFF's test split has only ~15 questions, so its intervals are wide.
  • Safety: without the same-source restriction, shortcuts alone reach 0.97, because some sources (e.g. a 0.5B model, jailbreak responses) are always the bad ones. That is why the headline compares within source.
  • Layer chart: dev split. "Would say at this layer" = that layer read through the model's own output head (logit lens).
